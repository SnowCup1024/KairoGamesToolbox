# 版本、构建与发布规范

返回 [贡献指南](../CONTRIBUTING.md)。按本次任务阅读相关章节。

## 版本与发布

根目录 `CHANGELOG.md` 随 Git 提交。每次启动器更新时完整重写该文件，只保留最新版本的日期、变更和验证限制；不得追加历史版本章节。长期版本摘要另维护在 `Docs/UpdateHistory.md`，随版本更新分点追加并提交；旧版本只依据仓库文档或提交证据总结，无记录时仅标注缺失，不补写猜测，不记录每轮开发过程。该文件是明确允许提交的产品更新历史，不属于开发日志。历史证据通过 Git 查看，日志不包含特定游戏名称、AppID 或专属实现细节。关于页直接读取内嵌的该文件，使用版本标题、日期和项目列表显示；更新日志正文同步维护四语言译文，不另存一份界面日志。发布说明以本次日志为基础，并标明正式发行版或预发行版。

仅在任务包含版本迭代或发布时更新版本；文档修订、清理和普通修复不自动升版。沿用以下版本映射，修改映射本身需要维护者明确要求或确认；按既定映射升级版本不需要额外确认。

- `v0.0.1`—`v0.2.4` 为早期测试阶段，保留历史，不重写旧版本语义。
- x 为重大阶段，y 为一般发布阶段，z 为阶段内测试迭代序号；z 从 1 开始，不允许为 0。
- 对外版本：测试版 `v2.3 Beta z`，正式版 `v2.3 Release`。默认展示不使用三段数字，也不添加 `(Beta)`；关于与设置页点击版本号可切换显示内部 `v2.3.z`，再次点击恢复。版本旁不拼接许可证，许可信息保留在关于页独立卡片中。
- 内部版本：测试 Beta z 对应 `2.3.z`；该阶段正式版使用最后一次测试序号加 1，例如 Beta 5 为 `2.3.5`，随后正式版为 `2.3.6`。正式版的加 1 是升级实际内部版本，不是显示时临时加 1。
- 启动器程序集和版本比较使用内部数字；启动器、文档及发布说明使用对外版本。游戏模组独立按日期管理，见 [模组规范](ModDevelopment.md)。
- 文件／目录名将对外版本中的空格换成连字符，例如 `v1.0-Release`；正式版使用 `v2.3-Release`。发布脚本 `-Version` 参数仍为内部三段版本。
- `ReleaseInfo.Version` 与 `ReleaseInfo.IsBeta` 是版本事实来源；用户可见版本由 `ReleaseInfo.DisplayVersion`／`FormatDisplay` 统一生成。正式发布时修改内部版本并设置 `IsBeta=false`。
- Beta 不创建正式发行版；用户明确要求时可创建 GitHub 预发行版，必须设置 `prerelease=true`。正式版才创建正式发行版。提交、推送和上传附件遵循本次会话授权。


## 发布与提交

每次完成会影响启动器或内嵌资源的开发更新，都必须运行一次交付构建脚本，生成可直接运行的 EXE 和 ZIP；开发中未升版的更新也执行，不能仅以 Debug 编译通过作为交付完成。纯文档、忽略规则或不影响产物的清理仍按验证表检查，无需重新构建。

本地交付构建与 GitHub 发行操作相互独立：不创建发行版或预发行版、不提交或不推送，都不免除交付构建。脚本只生成本地产物，不创建 GitHub 发行记录。`-Version` 使用 `ReleaseInfo.Version` 中的内部版本，必须与项目版本保持一致：

```powershell
# 示例：当前内部版本为 1.0.7；版本迭代时使用对应值。
.\Scripts\BuildRelease.ps1 -Version 1.0.7
```

脚本执行还原、Release 构建、启动器冒烟测试、单文件发布、启动检查与 ZIP 校验；不要再为同一发布重复执行这些步骤。其启动检查会打开并关闭脚本启动的验证进程，只证明创建主窗口，不证明界面流程或游戏行为通过。开发过程中同版本更新直接覆盖同名发布目录与 ZIP，使其始终对应当前源码；不为每轮更新另建带时间戳、序号或备份后缀的产物。仅在用户明确要求保留时另行处理。

全部发布步骤成功后，脚本自动删除 `.Build/Output` 和 `.Build/Obj`，保留 Publish、Package 及其他目录；发布失败保留编译缓存供排查。单独执行的 Debug 编译与测试不自动清理缓存；开发更新最后执行交付构建时，仍按上述成功条件清理缓存。清理失败仅警告“发布成功，但缓存清理失败”，不终止占用文件的进程，也不将成功产物报告为发布失败。发布期间不要并行构建同一仓库；检测到其他 .NET 构建／运行命令、无法检查进程或目标含重解析点时跳过缓存清理。

桌面不可用、用户要求不启动程序或存在运行实例等条件导致无法可靠检查时，使用 `-SkipLaunchCheck`，在交付说明中报告原因及待手测项，不预设使用者已经验证。产物位于 `.Build/Publish/<对外版本目录>` 与 `.Build/Package`。

提交与推送遵循本次会话中仍适用的用户授权；Beta 只可按授权创建预发行版，不创建正式发行版。提交前运行 `git diff --check`，审查本次差异与暂存文件；版本、载荷、许可、链接和忽略规则只在本次涉及时检查。提交标题使用简洁中文，描述最终行为；提交说明或合并请求报告相关验证及限制。可见界面变化在有截图能力与授权时附图，否则说明未截图，不阻塞其余工作。不要仅因提交次数或固定推送次数制造等待。
