# 开发与验证规范

返回 [贡献指南](../CONTRIBUTING.md)。按本次任务阅读相关章节。

## 仓库与技术分层

- 默认分支 `main`；若用户要求隔离分支，遵循其指定名称，否则新分支使用 `codex/` 前缀。
- `Windows/Core` 目标 .NET 8，必须独立于 WinUI，容纳可测试的识别、下载、安装事务、日志解析和通信。
- `Windows/Launcher/Source` 为 Windows x64 WinUI 应用，XAML 与对应 `.xaml.cs` 配对。页级控制逻辑可拆为 partial 文件。
- 游戏插件目标 .NET 6，使用匹配 BepInEx 运行时。不要仅为语言语法升级插件目标框架。
- .NET SDK 由 `global.json` 固定版本及补丁滚动。编译输出受 `Directory.Build.props` 管理，落入 `.Build`；临时夹具与自有载荷例外见下文。
- C# 使用四空格缩进、file-scoped namespace、独立行大括号、PascalCase 类型／方法、camelCase 参数／局部变量，保留 nullable 注解。
- Release 启用 `EnableCompressionInSingleFile=true`，项目文件与发布命令保持一致；继续自包含 .NET／WinUI，不删除运行库。IL 裁剪当前关闭：先处理反射／JSON 警告并验证实际发布产物，才能启用；禁止隐藏裁剪警告代替兼容性处理。包体优化必须分别记录 EXE 和 ZIP 大小，不能将 EXE 收益当作下载收益。
- 不进行无关格式化、大范围重命名或依赖升级。新增依赖需说明用途和发布体积影响。


## 文件、游戏与 Git 边界

- 外部 KairoMods 工作区不再作为依赖，也不得初始化或提交该目录。必要源码在仓库 `Mods`。用户可指定 Steam 安装目录或根目录 `.TestGames` 测试副本；不得假定已删除的旧游戏仍存在。
- 按游戏组织：`Mods/Games/<英文无空格游戏名>/Source`、`Payload`、`definition.json`。共用协议位于 `Mods/Shared`，许可位于 `Mods/Notices`。
- **允许提交**：自有源码、必要资源、声明式定义、许可文本、测试、中文使用说明和长期规范；根目录 `AGENTS.md` 是可提交的共享协作入口。自有插件 DLL 仅在 `Mods/Games/<标识>/Payload` 作为必要构建输入提交，变化时核对源码、版本一致性、构建结果和 SHA256，不泛化为所有二进制均可提交。
- **禁止提交**：商业游戏 EXE／GameAssembly／global-metadata、存档、游戏生成的 interop、BepInEx core、dotnet 运行时、完整模组 ZIP、`.Build`、`.TestGames`、下载缓存、备份、API Key、个人路径配置，以及开发日志、阶段验收清单、一次性计划、审查报告、原始日志和元数据导出。
- 临时记录优先留在任务中；确需落盘时使用 `.Build`。不在源码目录新增过程性文档，不将其改名为报告或归档后提交，不从长期文档链接这些临时材料。兼容忽略任意层级的 `DEVELOPMENT.md`，不再使用 `.Docs`。
- `.gitignore` 不能保护已跟踪文件；提交前检查实际暂存清单与差异，对新增或变化的二进制核对来源及体积。禁止用 `git add -f` 绕过上述规则。
- 项目维护文档使用中文；路径、命令、协议字段和代码标识保持原样。项目许可证与第三方许可文本保留上游原文，不以翻译替换授权内容；`.gitattributes` 仅对第三方许可目录关闭空白告警。
- 文件删除／迁移先解析绝对路径并确认位于授权目录。禁止混用多个 shell 构造删除命令；不自动删除外部旧包、测试存档或用户进程。
- 未经明确要求不隐藏启动游戏、不结束用户游戏进程、不使用界面自动操作工具。构建任务需要的启动器进程启动检查与界面操作、游戏内手测分别报告；不能进行后两者时，完成其余验证并集中列出受影响的待测场景，不为无关工作反复等待确认。


## 用户数据与非 Steam 游戏

- 配置、非 Steam 游戏库、封面与运行组件缓存统一放在 `%LocalAppData%\KairoGamesToolbox`，不放在 EXE 旁。
- API Key 使用 Windows DPAPI CurrentUser 加密；不写入日志。再次编辑时清空重填，未保存离开恢复掩码。
- Steam 路径必须验证 `Steam.exe` 与 `steamapps`，无效输入不能悄悄改用其他路径。
- 非 Steam 添加使用文件夹选择，要求 `KairoGames.exe` 与可信的 `KairoGames_Data/app.info` 身份；不能仅以路径名或同名 EXE 推测游戏。
- 移除非 Steam 只删库记录，不删除游戏或存档。目录自动填入详情页，但必须允许重新选择。


## 四语言与文字规范

- 支持 `zh-CN`、`zh-TW`、`en`、`ja`。语言选项放在设置中主题的上方，语言名称使用各自语言的自称。
- 普通界面文案、按钮、tooltip、辅助功能名称、空态、验证失败与应用自有错误均须本地化。XAML 使用 `TextExtension`，C# 使用 `L.T`／`L.F`。带参数文字使用占位符而非先插值再翻译。
- 译文集中于 `Windows/Core/Localization.json`；功能与日志规则的四语言文字在对应游戏 `definition.json`。占位符个数与格式必须一致，测试使用 `TestLocalization.ps1`。
- 游戏名称以 Steam 对应语言为主要来源，必要时使用可靠 Wiki。保存来源与核对时间。不得把猜测或机械繁简转换标成官方译名。官方简体页面返回繁体／英文复合名时，可保留已有正确简体短名，同时记录原始标题。
- 英文规范名、AppID、协议 ID、哈希、路径、配置键不能随语言改变。搜索保留英文、中文及拼音／首字母能力；显示语言不改变游戏身份。
- 统一样式：页面主标题 `PageTitleStyle`（28、SemiBold），卡片标题 `SectionTitleStyle`（20、SemiBold），字段／子标题 `LabelStyle`（14、SemiBold），正文 14、Normal，辅助小字 12、Normal。标题与副标题必须加粗，正文不随意加粗。
- 同级语义使用同级样式；Steam 路径与游玩记录是「Steam 相关」的同级子项，放在同一卡片内。主题和语言也是同级字段。
- 正文支持换行，长路径、英文／日文标题与窄窗口不得撑破右边界。每项按「文字、开关、倍率标记与滑动条」同一行排列，禁止把滑动条换到下一行。每行最多两项，空间不足时一项。各项标签列按当前语言最长文字的实际测量宽度对齐，不能硬编码中文长度；窗口与语言变化时重新计算。拖动时本地即时预览，松手／键盘输入停顿后合并发送，不能每档禁用并回填旧值。
- 游戏详情头部只保留封面、32 号游戏标题及启动／下载／商店按钮，不重复显示模组管理、拥有状态或 AppID。已拥有未安装的 Steam 游戏显示“下载游戏”，调用 `steam://rungameid/<AppID>`；未拥有或拥有状态未知时仍打开商店。只有检测到当前游戏的专用模组文件及安装标识时才显示「模组控制」，未安装、切换至无模组目录或卸载后自动回到管理页。游戏详情使用「游戏目录与模组状态」「模组控制」两页签，不再出现 01／02／03 编号。沿用主题、卡片与过渡动画，不嵌入裸外部窗口充当 UI。


## 清理与文档维护

- 构建、发布、下载、导出和诊断输出统一放在 `.Build`。测试可使用系统临时目录中的独立合成夹具，并在结束时清理；自有插件载荷按文件边界作为显式例外维护。
- 清理只处理本次任务确定的目录和文件。先解析绝对路径，验证目录边界及重解析点；有指定保留的发布文件时对比清理前后 SHA256，不递归删除其父目录。
- 区分源码、自有载荷、用户数据与可重建输出。包含商业游戏、存档、配置或用途不明内容的目录不能自动当作垃圾。
- 清理后以目录清单、必要哈希和 Git 差异验证，不重新构建来证明清理成功。正常构建之后可以重新生成缓存，不将一次清理留下的版本目录写成永久要求。
- CHANGELOG 仅维护最新版本变更；Docs/UpdateHistory 维护有证据的历代版本摘要；README 维护用户使用说明；CONTRIBUTING 维护索引，Docs 中各规范按职责维护；Mods/README 只维护模组汇总；游戏专属功能、接口、构建与验证说明放在 Mods/Games/<标识>/README.md；AGENTS 维护简短协作入口。相同规则只在一个位置维护，其他文档按需链接。
- 不按每轮任务追加测试计数或工作日志；只有 `Docs/UpdateHistory.md` 按版本维护产品更新摘要。只在产品行为、约束或可复用经验发生变化时更新对应文档；详细过程留在任务或版本控制历史中。新增长期文档应有现有文档无法承载的明确职责。


## 按变更选择验证

以下是选择表，不是每次修改都依次执行的清单。针对本次变更运行适用检查，修复由本次修改导致的失败；相同输入和环境下已有通过结果可复用，没有新改动、失败或未解决疑点时不重复或扩大验证。

| 变更范围 | 自动检查 | 人工验证范围 |
| --- | --- | --- |
| 文档、忽略规则、清理 | 差异、链接、文件清单和忽略规则；保留产物时核对哈希 | 无需启动程序或游戏 |
| 核心业务逻辑 | `dotnet run --project Windows/Test/LauncherSmokeTest.csproj`，补充受影响行为的有效检查 | 仅涉及真实界面或游戏行为时补测 |
| 启动器界面 | `dotnet build Windows/KairosoftGameToolbox.sln --configuration Debug`；文字变化时运行 `Scripts/TestLocalization.ps1` | 受影响页面；布局检查相关语言、主题、窄窗口与长文字，安装或连接流程变化时补测对应流程 |
| 模组结算或单游戏控制 | 运行模组控制测试，筛选参数和编译方式见对应游戏说明 | 受影响资源的关闭／开启、0／1／50 倍、实际扣除、正常收入及对象归属；加载保护变化时验证保存加载 |
| 共用协议或状态生命周期 | 模组控制测试项目的完整检查；启动器相关逻辑同时跑冒烟测试 | 受影响游戏的断线、重连、退出和会话隔离 |
| 安装事务或运行组件 | 安装回退、未知文件保留、哈希及路径检查；真实运行组件组合验证按本文件说明执行 | 受影响的安装、更新或删除流程 |
| 交付发布包 | [交付构建流程](Release.md)及此次涉及但尚未覆盖的检查 | 启动器实际启动；新增完整模组覆盖全部需求功能与档位，修复按影响范围复测 |

- 使用现有 `Check` 可执行测试框架；新检查放在 `Windows/Test` 或 `Mods/ControlTests` 中职责对应的文件，不要求全部塞入入口文件。重点验证行为和边界，不添加只镜像实现的检查。
- 合成 Steam／游戏目录的测试不访问真实 Steam、存档或外部服务。首次还原 .NET 依赖可能联网，不等于测试本身依赖网络。
- `Scripts/TestBundledRuntime.ps1` 是显式联网校验：缺缓存时下载官方运行组件，再校验 SHA256、内容和组合包，并运行模组控制检查。仅在运行组件、组合安装路径变化或发布需要此项证据时执行；普通文档或 UI 修改不执行，不另重复同一轮已覆盖的控制检查。
- 重编插件的命令及依赖见 [模组目录](../Mods/README.md)中的对应游戏构建说明。目标指纹和载荷完整性校验不能跳过；普通启动器构建不应因此要求安装商业游戏。
- 界面手测、游戏真实消费和长期稳定性无法由编译、静态签名或管道夹具证明。只报告实际验证范围，历史无响应没有对应证据时不宣称已解决。缺失证据只阻塞依赖它的工作。
